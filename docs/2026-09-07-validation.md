## 확인한 증거와 테스트

- 설치본 로그에서 `Global mouse tracker could not start`가 반복됨을 확인했다. 코드에서 MainWindow와 GlobalMouseTracker가 동일한 Ctrl+Alt+Esc 조합을 등록했고 두 번째 등록 실패가 추적기 전체를 종료했다.
- Release 빌드: 경고 0, 오류 0.
- .NET 회귀 테스트 28개 통과. 실제 루프백 TCP 두 인스턴스로 텍스트/이미지 페이로드와 수신 응답, 이름 갱신, 양방향 추적기 시작/종료, 모니터 정보 수신, 파일 전송 및 완료 파일 경로를 확인했다. 물리 입력이나 Windows 클립보드 적용까지 통과했다는 의미는 아니다.
- Node 모바일 제스처 테스트 통과: 세로 스크롤 방향, 두 손가락 탭, 취소, 펜 중앙 좌표, 미리보기 요청.
- 브라우저에서 844×390 가로 및 390×844 세로 레이아웃 확인. 가로 화면의 패드와 도구막대 사각형이 겹치지 않음을 확인했다. 화면 미리보기의 실제 내용은 실기기 검증 대상이다.
- 기존 WPF 테스트가 앱 시작 코드까지 실행하여 설치된 앱의 기본 포트와 충돌하는 문제를 테스트 전용 시작 스위치로 분리했다. 설치된 앱은 종료하거나 교체하지 않았다.
- `git diff --check` 통과. 로컬 변경은 아직 커밋하지 않았다.

## 재현/검증 실행

```powershell
dotnet run --project tests/CrowLink.Tests/CrowLink.Tests.csproj -c Release
node tests/mobile-gestures.cjs
```

프로젝트 지정 SDK는 .NET 10.0.302이다. 두 PC 검증은 양쪽 모두 동일한 수정 소스로 수행한다. 기존 설치본은 수정 전 소스이므로 그대로 실행해서는 수정 검증이 되지 않는다. ARM 기종과 운영체제가 아직 확인되지 않았다. 이 저장소는 WPF 기반 Windows 앱이며 macOS 실행을 지원하지 않는다.

송신 완료 알림은 기존 전송 서비스 기준으로 소켓 송신 완료를 의미한다. 최종 저장 성공은 수신 PC의 완료 활동/알림으로 확인한다. 단일 연속 PC 간 OLE 드래그는 구현하지 않았고, Activity의 드래그는 수신된 로컬 파일을 탐색기에 복사하는 동작이다.
